## 2026-07-07 Cloudflare Pages Direct Upload 不能原地转 Git 集成

### 现象

项目已通过 `wrangler pages deploy` 直接上传上线，随后尝试用 Cloudflare Pages Project API 给同一个 Pages 项目补充 GitHub `source`，API 返回：

```text
You cannot update the source object in a Direct Uploads project.
```

### 原因

Cloudflare Pages 的 Direct Upload 项目和 Git Integration 项目类型不同，现有 Direct Upload 项目的 `source` 不能被原地更新为 GitHub 仓库。

### 解决方案

- 已保留当前线上 Direct Upload 项目，避免影响 `https://palworld-1-0-guide-hub.pages.dev/`。
- 已完成 GitHub `main` push，并设置 Cloudflare Pages `PUBLIC_SITE_URL` 普通环境变量。
- 如需同名 Git 集成，需要先删除当前 Direct Upload 项目，再创建同名 Git 集成项目。
- 如不想影响当前线上站，可以新建另一个 Git 集成 Pages 项目。
- 用户确认站点尚未正式推广后，已删除旧 Direct Upload 项目并重建同名 GitHub 集成 Pages 项目；Cloudflare 项目列表显示 `Git Provider: Yes`。
- 重建后需要触发一次 production deployment；本项目通过 Cloudflare Pages deployments API 触发并成功部署。

### 是否值得写入全局踩坑日志

值得。以后内容站如果最终要 Git 自动部署，应优先通过 Dashboard/API 创建 Git Integration 项目，不要先创建同名 Direct Upload 项目。
